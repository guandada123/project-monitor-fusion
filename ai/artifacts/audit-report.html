🔴 P0 — 高危（安全与数据完整性）

✅
P0-1：集成凭据以明文暴露在前端 DOM
Livewire `public` 属性泄露 GitHub Token / 飞书 App Secret / 钉钉 Secret → 改用 `#[Locked]` 属性，敏感字段不再序列化到前端
✅
P0-2：被忽略的 Composer 安全公告（4 个 PKSA）
`composer.json` 的 `config.audit.ignore` 中忽略 4 个 PKSA 公告 → 逐一审查后确认误报，保留带注释的 ignore（PKSA-mdq4 / PKSA-8qx3 / PKSA-q46n / PKSA-qzrn）
✅
P0-3：Nginx 缺少 Content-Security-Policy 头
缺少 CSP 头，XSS 防御不足 → 添加完整 CSP（`script-src 'self' 'nonce-$request_id' 'unsafe-eval'`），移除废弃的 `X-XSS-Protection`，新增 `Permissions-Policy`
✅
P0-4：Logout 路由缺少认证中间件保护
`/logout` 可被匿名用户访问 → 添加 `middleware('auth')`，同时重构为 `LogoutController`（P2-2）
✅
P0-5：Entrypoint 中 `key:generate --force` 可能破坏生产加密数据
生产环境可能因空 `APP_KEY` 自动重生成密钥 → 添加环境检测：生产环境 `APP_KEY` 为空时直接 `exit 1`，仅开发/演示环境允许自动生成

🟠 P1 — 中危（性能与代码质量）

✅
P1-1：Dashboard 循环内 N+1 查询（42 SQL/渲染）
循环 7 天 × 3 类 + 7 天 × 3 指标 = 42 条 SQL → GROUP BY 批量聚合，42 → 6 条 SQL，加载时间预估 ~300ms → ~50ms
✅
P1-2：Project Model Accessor 触发隐式数据库查询
`completion_rate` / `overdue_rate` / `open_risk_count` 每次调用触发独立 SQL → 添加 `relationLoaded()` 保护，预加载关系后零额外 SQL
✅
P1-3：定时任务缺少 `withoutOverlapping()` 防并发保护
`risk:scan`（30 分钟）和 `metrics:collect`（每小时）可能重叠运行 → 添加 `withoutOverlapping()` + `runInBackground()`
✅
P1-4：Livewire CSP 安全模式未启用
`config/livewire.php` 中 `csp_safe` 默认关闭 → 启用为 `true`，配合 Nginx CSP 头实现 nonce 级脚本白名单
✅
P1-5：Unit 测试目录完全空白
`tests/Unit/` 目录无任何测试文件 → 新增 `ProjectAccessorTest`（7 tests）+ `RiskDetectorTest`（11 tests），修复 flaky 随机状态问题
✅
P1-6：`SESSION_ENCRYPT=false` 默认未启用
`.env.example` 显式关闭 Session 加密 → 改为 `SESSION_ENCRYPT=true`（纵深防御）
✅
P1-7：Integration `findOrFail()` 缺少权限作用域隔离（IDOR）
6 个方法直接使用 `Integration::findOrFail($id)` 无资源级权限检查 → 添加 `authorizeIntegration()` 方法覆盖所有关键操作

🟡 P2 — 低危（最佳实践改进）

✅
P2-1：`X-XSS-Protection` 头已被现代浏览器废弃
已在 P0-3 随 CSP 添加自动移除
✅
P2-2：Logout 使用路由闭包而非 Controller
新建 `LogoutController`（单动作 `__invoke()`），路由改为 `LogoutController::class`，可单元测试、可复用
✅
P2-3：README 仍为 Laravel 默认模板内容
完全重写为项目专属 README，涵盖功能概览、技术栈、部署、架构、测试、安全等
✅
P2-4：`settings.json` 不适合生产配置存储
迁移到数据库表（`settings` 表 + `Setting` Model + `SettingsService`），支持缓存、分组操作、类型转换，8 条设置自动导入
✅
P2-5：Nginx 无登录速率限制（防暴力破解）
添加 `limit_req_zone`（5r/m）+ location 限流块（burst=5, nodelay, 429），配合 Laravel throttle 双重防护
✅
P2-6：Docker 容器以 root 权限运行
添加 `USER www-data`，安装 `su-exec`，构建阶段预先执行 `storage:link`，entrypoint 中 `key:generate` 降级处理
